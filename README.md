# 節税・資産形成ナビ v1

## アプリを使う

[節税・資産形成ナビを開く](https://tngmshr.github.io/setsuzei-navi/)（[制度の解説](https://tngmshr.github.io/setsuzei-navi/#guide)）

初心者の会社員がスマートフォンで使う、節税と資産形成の整理用Webアプリです。2026年所得・2027年度住民税の簡易モデルに固定しています。個別の税務・投資助言は行いません。

## 起動

`index.html` をブラウザで開きます。依存ライブラリ、ビルド、アカウント登録は不要です。PWA・オフライン機能はHTTPS配信またはlocalhostでのみ利用できます。公開版は https://tngmshr.github.io/setsuzei-navi/ です。

## ファイル

| ファイル | 内容 |
| --- | --- |
| `index.html` | 日本語の画面・CSS・素のJavaScript。入力、優先順と金額、年間予定の3画面 |
| `params.js` | 制度値・出典URL・確認日。制度値と説明用の仮定を分離 |
| `calc.js` | 入力の検証、給与所得・控除・所得税・iDeCo・寄付上限の純粋関数、カレンダー生成 |
| `link.js` | ふるさと納税ナビとの連携（`furusatoNavi.log` の読み取り。年ごとの上限 `limits` と以前の形式に対応、`setsuzeiNavi.share.v1` の書き込み・削除）。保存領域なし・空・壊れたJSON・古い配列形式でも例外を出さない。寄付の集計は上限の目安と同じ `params.js` の `year` 年分（年が明けても前年分の確認に使える）。`year` が今年で1〜3月のときは前年分の合計も出す（上限とは比べない）。入力の途中で不正になっても、最後に計算できた目安は消さない |
| `test/calc.test.js` | `node:test`。期待値の手計算式と出典付き |
| `test/link.test.js` | 連携の読み書きのテスト（ふるさと納税ナビの実際の保存形式と受け入れ条件に合わせる） |
| `test/index.js` | Nodeでディレクトリを指定して実行するための入口 |
| `manifest.webmanifest`・`sw.js` | PWA設定・ネット優先キャッシュ |

ブラウザからは `SetsuzeiParams`・`SetsuzeiCalc`・`SetsuzeiLink`、Nodeからは `require('./params.js')`・`require('./calc.js')`・`require('./link.js')` で読み込めます。

## 入力と表示

仕様の入力項目をすべて任意入力で用意しています。空欄は年収の目安500万円、35歳、配偶者なし、子なし、企業年金なし、社会保険料は年収の15%、生活防衛資金3か月、月の積立予算の目安30,000円という説明用仮定です。iDeCo試算は月の目安10,000円を初期仮定にし、結果画面で変更できます。仮定と実際に計算へ使用した値は結果の展開欄に列挙します。

企業年金を「分からない」と選んだ場合、企業年金ありで必要な掛金が空欄の場合、60歳以上で加入条件が未確認の場合は、そのiDeCo上限を推測しません。マッチング拠出中・老齢基礎年金やiDeCo老齢給付金の受給中は対象外とします。60歳以上の資格は勤務先・運営管理機関で確認済みの入力を必要とします。70歳以上の特殊な加入資格は扱いません。

生活防衛資金が3か月分未満の場合は現金の備えを最優先にし、NISAとiDeCoを「貯まってから」と表示します。保険料・医療費・住宅ローンの確認項目は該当する場合にだけ表示します。

### 未確認の値と、計算への影響

指定された省庁・iDeCo公式の本文で確認できなかった以下は、`params.js` に `null` を置いています。自治体公式資料の数値を、許可なく制度値へ採用していません。

- **住民税の調整控除**：計算式・基礎差・人的控除差を指定省庁本文で確認できませんでした。このため調整控除後の所得割と、それに依存する**ふるさと納税上限は現在すべて「確認中」**です。逆算する純粋関数自体は実装・単体検証済みです。総務省直下のページは本文取得不可。[千葉市の公式説明](https://www.city.chiba.jp/zaiseikyoku/zeimu/kazeikanri/kojinshotokuwarisanshutu.html)では確認可能ですが、指定省庁外の資料として未採用です。
- **本人所得900万円超〜1,000万円以下の住民税配偶者控除の逓減額**：総務省資料では逓減することだけ確認。額は `null`。[長野市の公式説明](https://www.city.nagano.nagano.jp/n062000/contents/p005573.html)は補足資料として扱います。
- **住宅ローン控除の住民税上限**：入居年等で変わる標準上限・旧制度上限を指定省庁本文で確認できず `null`。年額だけでは入居年・取得条件・申告方法を決められないため、住宅控除ありの寄付上限は「確認中」です。[自治体の改正説明](https://www.city.hiroshima.lg.jp/living/zei/1006016/1025582/1051560.html)は未採用の補足資料です。

現状は画面・iDeCo等の計算を実装した状態で、寄付上限の数値表示まで含む仕様の完全達成には未確認値の解消が必要です。

## 計算上の注意

- iDeCoの年間節税額は、月額×12×（所得税率×1.021＋住民税率10%）の簡易式。さらに税率変化を反映した税額差の欄もありますが、住民税の未確認値がある間は後者も確認中です。税額控除・手数料・受取時課税は差額に含めません。所得税・住民税の課税所得が共にゼロなら節税額もゼロとします。
- 改正後の掛金を12か月払う場合の比較です。2026年中に新上限で12か月払える意味ではありません。掛金変更の締め日は運営管理機関で確認します。
- 寄付上限の式は、2,000＋調整控除後住民税所得割×20%÷（90%−所得税率×1.021）。所得税率は所得税の課税所得から求める簡易モデル。税率の境目を寄付額でまたぐケース、地方税側の率判定差、非課税判定、超過課税等は最終確認が必要です。
- 住宅控除を住民税所得割から直接引いて、寄付上限を一律に下げる計算はしません。住宅ローン控除は手続きと税目ごとの残枠で影響が変わります。
- 配偶者は70歳未満を仮定。共働きの配偶者特別控除、子の特定親族特別控除、障害者・ひとり親等の控除は未対応。保険料・医療費控除も試算には未反映です。
- 自営業・公務員・年収2,000万円超・大きな副業所得は対象外です。

## 保存とプライバシー

- 入力は `localStorage` の **`setsuzeiNavi.inputs.v1`** にだけ保存。消去操作もこのキーだけを対象にします。
- 外部送信・解析・外部ライブラリ・個人値入りのURLを使いません。画面移動は `#input` 等の固定ハッシュだけです。
- Googleカレンダーのリンクと `.ics` は一般的な予定名・日付・説明のみ。入力値を含めません。Google側の登録操作は利用者が行います。
- スクリプト実行・接続先をCSPで制限し、外部リンクは参照元を送らない設定です。
- ストレージ拒否・保存データ破損でも起動・計算できます。
- サービスワーカーは自アプリの静的ファイルだけをネット優先でキャッシュします。入力値はキャッシュしません。古いキャッシュの削除は本アプリの接頭辞だけに限定しています。

## 引き継ぎ時の状態

この実行環境は `.git` が読み取り専用です。`git add` は `.git/index.lock: Permission denied` で失敗し、コミットは作成できていません。指定の共有引き継ぎログも書き込み可能な範囲外です。追記用文面と指定形式のコミットメッセージを `outputs/` に置きます。Gitメタデータの権限や既存設定は変更していません。
